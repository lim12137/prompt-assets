# 操作手册

适用对象：提示词管理系统的使用者、管理员和维护者。

本项目是一个可自建、可内网部署的提示词资产管理系统。当前代码形态是 pnpm monorepo，包含 Next.js Web 应用、PostgreSQL/Drizzle 数据层、领域逻辑包、Playwright 与 Node 测试脚本。

## 1. 项目结构

```text
apps/web/        Next.js Web 应用，包含首页、详情页、登录页、管理页和 API 路由
packages/db/     PostgreSQL schema、迁移、种子数据脚本
packages/domain/ 版本号、审核流、审计等领域逻辑
scripts/         本地调试、真实库 E2E、性能测试辅助脚本
tests/           单元测试、集成测试、E2E 测试、测试夹具
docs/            方案、测试报告、部署与操作文档
docker-compose.yml 生产/内网运行示例，使用 GHCR 镜像启动 Web 与 PostgreSQL
```

## 2. 环境准备

必需环境：

- Node.js 22，项目根目录 `.nvmrc` 指定为 `22`
- pnpm 10.11.0，根 `package.json` 的 `packageManager` 已固定
- Git

按需安装：

- Docker Desktop 或 Docker Engine，用于本地 PostgreSQL、测试库、Compose 部署
- PostgreSQL 客户端工具，用于排查数据库连接和数据

首次拉取代码后安装依赖：

```powershell
pnpm install
```

## 3. 配置说明

项目根目录的 `.env.example` 给出了主要运行配置。常用变量如下：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | Web 与数据库脚本使用的 PostgreSQL 连接串。生产运行必须配置。 |
| `APP_BASE_URL` | 应用外部访问地址，本地默认可用 `http://localhost:3010`。 |
| `PROMPT_REPOSITORY_DATA_SOURCE` | 数据来源模式。`fixture` 使用内置测试数据，`auto` 使用真实数据库。 |
| `LOGIN_TOKEN_SECRET` | 登录态签名密钥。启用登录和管理功能时必须配置。 |
| `AWS_PORTAL_URL` | OA 登录接口地址。登录页会调用该地址校验账号密码。 |
| `WHITELIST_ENABLED` | 是否启用管理白名单。 |
| `WHITELIST_DEFAULT_IDS` / `WHITELIST_DEFAULT_NAMES` | 可管理提示词的用户 ID/姓名白名单。 |
| `WHITELIST_ADMIN_USER_IDS` / `WHITELIST_ADMIN_USER_NAMES` | 可管理白名单的管理员 ID/姓名。 |
| `ALLOW_ALL_LOGIN_USERS_MANAGE` | 未启用白名单时，是否允许所有登录用户进入管理操作。仅建议本地调试使用。 |
| `AI_TOOLS` 与 `AI_TOOL_*` | 首页 AI 工具入口配置，当前要求正好 3 个工具。 |
| `GHCR_OWNER`、`WEB_IMAGE_TAG`、`POSTGRES_IMAGE_TAG` | Docker Compose 拉取镜像时使用。 |
| `WEB_PORT`、`POSTGRES_PORT` | Compose 暴露端口。 |

数据库连接规则：

- 如果存在 `DATABASE_URL`，优先使用该连接串。
- 如果没有 `DATABASE_URL`，会根据 `POSTGRES_HOST`、`POSTGRES_PORT`、`POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` 组装。
- 默认组装结果是 `postgres://postgres:postgres@127.0.0.1:5432/prompt_management`。

## 4. 本地启动

### 4.1 无数据库快速试用

适合只查看页面和交互，不验证真实数据库写入。

```powershell
$env:DATABASE_URL="postgres://postgres:postgres@127.0.0.1:1/prompt_management"
$env:PROMPT_REPOSITORY_DATA_SOURCE="fixture"
$env:LOGIN_TOKEN_SECRET="local-dev-secret"
$env:ALLOW_ALL_LOGIN_USERS_MANAGE="true"
pnpm dev:web
```

启动后访问：

- 首页：`http://127.0.0.1:3010`
- 健康检查：`http://127.0.0.1:3010/api/health`
- 登录页：`http://127.0.0.1:3010/login`
- 管理页：`http://127.0.0.1:3010/admin`

说明：

- `fixture` 模式使用 `tests/fixtures/prompts.ts` 中的内置数据。
- 该模式适合前端展示和 API 行为调试，不代表生产数据状态。

### 4.2 使用真实 PostgreSQL

准备 `.env`：

```powershell
Copy-Item .env.example .env
```

至少确认或补充：

```dotenv
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/prompt_management
APP_BASE_URL=http://127.0.0.1:3010
LOGIN_TOKEN_SECRET=replace_with_long_random_secret
PROMPT_REPOSITORY_DATA_SOURCE=auto
```

执行迁移与种子数据：

```powershell
pnpm db:migrate
pnpm db:seed
```

启动 Web：

```powershell
pnpm dev:web
```

如果需要通过项目脚本管理本地调试库，可使用：

```powershell
pnpm local:db:up
pnpm local:prepare
pnpm local:dev
```

注意：`scripts/local-debug.mjs` 带有默认远程调试库地址。使用前请确认 `.env` 或当前 PowerShell 环境中的 `LOCAL_POSTGRES_HOST`、`LOCAL_POSTGRES_PORT`、`LOCAL_POSTGRES_DB`、`LOCAL_POSTGRES_USER`、`LOCAL_POSTGRES_PASSWORD` 是否指向预期数据库。

## 5. Docker Compose 启动

`docker-compose.yml` 面向内网部署，默认从 GHCR 拉取：

- `ghcr.io/${GHCR_OWNER}/prompt-assets-web:${WEB_IMAGE_TAG}`
- `ghcr.io/${GHCR_OWNER}/prompt-assets-postgres:${POSTGRES_IMAGE_TAG}`

步骤：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，至少设置：

```dotenv
GHCR_OWNER=实际镜像 owner
WEB_IMAGE_TAG=实际 Web 镜像标签
POSTGRES_IMAGE_TAG=16-alpine
WEB_PORT=13000
POSTGRES_PORT=5432
POSTGRES_DB=prompt_management
POSTGRES_USER=postgres
POSTGRES_PASSWORD=请替换强密码
APP_BASE_URL=http://localhost:13000
```

启动：

```powershell
docker compose up -d
docker compose ps
```

访问：

- Web：`http://localhost:13000`
- 健康检查：`http://localhost:13000/api/health`

停止：

```powershell
docker compose down
```

数据库数据保存在命名卷 `prompt_assets_postgres_data`。如果要清空数据，需要明确删除该卷，执行前请先备份。

## 6. 核心功能使用

### 6.1 首页浏览与搜索

首页 `/` 展示提示词卡片和首页 AI 工具入口。使用者可以：

- 按分类浏览提示词
- 使用顶部搜索定位提示词
- 查看提示词摘要、分类、点赞和版本信息
- 点击卡片进入详情页

首页 AI 工具入口由 `AI_TOOLS` 和 `AI_TOOL_*` 变量配置。当前运行时校验要求正好配置 3 个工具。

### 6.2 详情页

详情页路径为 `/prompts/{slug}`。使用者可以：

- 查看当前发布版本内容
- 一键复制提示词正文
- 查看版本历史
- 对提示词或具体版本点赞
- 按场景提交 1 到 5 分评分
- 基于当前版本提交改进版

### 6.3 登录与权限

登录页为 `/login`。登录流程会调用 `AWS_PORTAL_URL` 指向的 OA 服务：

- `POST /portal/r/jd` 校验账号密码
- `POST /portal/r/w` 读取用户姓名、部门等信息

登录成功后，系统签发由 `LOGIN_TOKEN_SECRET` 签名的 Cookie。管理权限由白名单相关变量或 `ALLOW_ALL_LOGIN_USERS_MANAGE` 决定。

### 6.4 管理操作

常用管理入口：

- `/admin`：审核用户提交的新版本
- `/admin/create`：创建提示词
- `/admin/import`：批量导入提示词
- `/admin/prompts`：提示词管理
- `/admin/prompts/{slug}`：单个提示词管理详情

管理员可以执行：

- 创建提示词及首版内容
- 导入提示词
- 审核通过或拒绝用户提交
- 编辑提示词元信息
- 归档、恢复、删除提示词
- 批量删除和批量调整分类

导入接口按全有或全无策略处理，同一批次中有冲突或非法项时会整体失败。

## 7. 数据与维护

### 7.1 主要数据表

核心表定义在 `packages/db/src/schema.ts`：

| 表 | 说明 |
| --- | --- |
| `users` | 用户及角色 |
| `categories` | 分类 |
| `prompts` | 提示词主表 |
| `prompt_categories` | 提示词多分类关系 |
| `prompt_versions` | 提示词版本正文与变更说明 |
| `submissions` | 用户提交与审核状态 |
| `prompt_likes` | 提示词点赞 |
| `prompt_version_likes` | 版本点赞 |
| `prompt_version_scores` | 版本评分 |
| `prompt_version_daily_interactions` | 版本互动日频限制 |
| `audit_logs` | 审计日志 |

### 7.2 迁移与种子

生成迁移：

```powershell
pnpm db:generate
```

执行迁移：

```powershell
pnpm db:migrate
```

写入种子数据：

```powershell
pnpm db:seed
```

默认种子脚本会重置核心种子表。如需避免重置，可设置：

```powershell
$env:DB_SEED_RESET="false"
pnpm db:seed
```

### 7.3 测试库

启动测试数据库：

```powershell
pnpm db:test:up
pnpm db:test:migrate
pnpm db:test:seed
```

关闭测试数据库：

```powershell
pnpm db:test:down
```

如本机端口冲突，可设置 `TEST_DB_PORT`、`TEST_DB_CONTAINER` 等变量后再启动。

## 9. 故障排查

### 9.1 启动时报 `DATABASE_URL is required`

原因：Web 启动前会校验运行环境。

处理：

- 本地真实库运行时，在 `.env` 写入有效 `DATABASE_URL`。
- 仅做页面试用时，也需要设置一个占位 `DATABASE_URL`，并设置 `PROMPT_REPOSITORY_DATA_SOURCE=fixture`。

### 9.2 首页看到的不是数据库数据

检查：

```powershell
$env:PROMPT_REPOSITORY_DATA_SOURCE
```

如果值为 `fixture`，系统会使用测试夹具数据。真实库模式应设置为 `auto` 或删除该变量，并确保数据库可连接。

### 9.3 管理页提示未登录或无权限

检查：

- `LOGIN_TOKEN_SECRET` 是否已配置
- `AWS_PORTAL_URL` 是否可访问
- 当前用户是否在白名单中
- 本地调试时是否明确设置了 `ALLOW_ALL_LOGIN_USERS_MANAGE=true`

### 9.4 Docker Compose 拉取镜像失败

检查：

- `.env` 中 `GHCR_OWNER` 是否正确
- `WEB_IMAGE_TAG`、`POSTGRES_IMAGE_TAG` 是否存在
- 当前机器是否能访问 GHCR
- 内网环境是否需要先 `docker load` 离线导入镜像

### 9.5 端口被占用

常见端口：

- 本地 Web：`3010`
- Compose Web：`13000`
- PostgreSQL：`5432`
- 测试库：`55432` 及部分真实库 E2E 脚本使用的 `55434`、`55435`、`55436`

处理：

- 修改 `WEB_PORT`、`POSTGRES_PORT`、`LOCAL_WEB_PORT` 或 `TEST_DB_PORT`
- 停止旧的本地 Web 或测试数据库容器
- 使用 `pnpm local:web:restart` 重启本地 Web

### 9.6 AI 工具配置校验失败

`AI_TOOLS` 当前必须解析出 3 个工具，且每个工具需要 name、desc、url、icon、颜色和 order。新增自定义工具时，变量后缀会把 slug 中非字母数字字符转成下划线并转大写，例如 `ceic-chat` 对应 `AI_TOOL_CEIC_CHAT_NAME`。

## 10. 发布与备份建议

内网正式运行前建议：

- 更换 `POSTGRES_PASSWORD` 和 `LOGIN_TOKEN_SECRET`
- 禁止使用 `ALLOW_ALL_LOGIN_USERS_MANAGE=true`
- 固定镜像标签，不直接依赖 `latest`
- 配置反向代理和 HTTPS
- 定期备份 PostgreSQL 数据卷或逻辑备份
- 升级前先执行数据库备份和冒烟测试

最小冒烟检查：

```powershell
docker compose ps
Invoke-WebRequest http://localhost:13000/api/health
```

浏览器检查：

- 首页可打开
- 能进入一个提示词详情页
- 复制按钮有反馈
- 登录后可进入管理页
- 管理员能看到待审核或提示词管理列表
