# 批量操作与批量删除设计稿

## 目标

在现有提示词管理列表页上扩展一组低开销批量操作能力，让管理员可以直接在列表中完成：

- 全选
- 反选
- 批量增加分类
- 批量删除分类
- 批量删除提示词

同时保持当前“平级多分类”模型，不引入主分类概念，不新增独立管理页面。

## 现状

当前列表页已经具备：

- 状态筛选
- 关键词筛选
- 分类筛选
- 卡片级多选
- 固定底部批量操作条
- 批量增加分类
- 批量删除分类

当前仍缺：

- 列表工具区的全选/反选
- 列表批量删除提示词
- 未分类快速筛选入口
- 删除提示词的列表内二次确认交互

详情页已经存在单条删除提示词能力，因此批量删除并不是从零设计后端语义，而是把现有删除模型扩展到列表批量操作。

## 设计原则

### 1. 最小增量

继续复用现有列表页、筛选区、卡片结构、固定底部浮层，不新开单独批量管理页面。

### 2. 性能优先

批量操作应尽量保持：

- 不整页 reload
- 不跳转路由
- 不重建页面上下文
- 操作后只按当前筛选条件重新收敛当前列表

### 3. 模型一致

分类保持平级多分类：

- 不再引入主分类选择
- 批量增加分类是“追加关联”
- 批量删除分类是“删除关联”
- 若删除后没有任何正式分类，则回落到系统待分类

### 4. 风险显式

批量删除提示词属于高风险操作，必须有二次确认区，并明确提示“删除的是提示词本体，不是分类关联”。

## 交互设计

## 列表页顶部

在现有筛选区基础上增加：

- `未分类` 快捷筛选
- `全选`
- `反选`

其中：

- `全选` 作用于当前筛选结果集
- `反选` 作用于当前当前可见结果集

这里不做“跨分页全选”语义，避免状态复杂化和性能负担。

## 列表卡片

保留当前每卡片左侧复选框，不改变卡片点进详情的主交互。

需要保证：

- 点复选框不会误触发进入详情
- 点卡片空白区仍进入详情

## 固定底部批量浮层

当选中数量大于 0 时显示，包含：

- 已选数量
- 批量增加分类
- 批量删除分类
- 批量删除提示词
- 清空选择

浮层是固定底部，不依赖滚动到列表末尾才出现。

## 批量增加分类

点击后在浮层内展开一个轻量面板：

- 展示可选分类列表
- 支持多选
- 点击确认后批量追加到选中提示词

成功后：

- 当前筛选条件保持不变
- 当前 URL 保持不变
- 列表按当前筛选重新收敛
- 选中态清空

## 批量删除分类

点击后在浮层内展开一个轻量面板：

- 只展示当前选中集合中实际存在的分类
- 支持多选
- 点击确认后删除这些分类关联

删除规则：

- 只删提示词与分类的关联
- 不删除分类本身
- 若某条提示词删完后没有正式分类，则自动归入待分类

成功后：

- 当前筛选条件保持不变
- 列表按当前筛选重新收敛
- 选中态清空

## 批量删除提示词

点击后不直接提交，而是在浮层内切换到风险确认态，显示：

- 即将删除的提示词数量
- 风险说明
- 删除影响说明
- 二次确认按钮
- 返回取消按钮

文案重点：

- 删除的是提示词本体
- 分类关联、版本、候选相关数据会一起受影响
- 该操作不可逆

确认后才真正请求后端批量删除接口。

成功后：

- 当前筛选条件保持不变
- 列表按当前筛选重新收敛
- 选中态清空

## 数据与接口设计

## 现有接口复用

批量增加分类 / 批量删除分类继续复用已有批量分类接口。

请求语义保持：

- `slugs`
- `addCategorySlugs`
- `removeCategorySlugs`

## 新增接口

需要新增一个批量删除提示词接口。

建议语义：

- 输入：提示词 `slugs[]`
- 支持删除预检查
- 支持确认 token

这样可以和现有单条删除接口保持一致的安全模型，而不是另起一套粗暴删除路径。

## 列表更新策略

列表不做整页刷新。

每次批量操作成功后执行：

1. 保留当前筛选 state
2. 重新请求当前列表数据
3. 仅更新列表数据区
4. 不跳转页面
5. 不重置筛选输入
6. 不保留旧的勾选集

这样比“只改本地 pills”更安全，因为分类筛选下需要重新收敛结果集。

## 错误处理

### 批量分类失败

- 浮层保留当前展开态
- 显示错误提示
- 保留用户当前选择，方便重试

### 批量删除失败

- 不清空选择
- 保留确认态
- 明确显示失败原因

### 部分记录失败

本次不做部分成功 UI。

后端应优先保证一批操作作为一个整体成功或失败，减少前端复杂度。

## 测试策略

### 列表交互 E2E

需要覆盖：

- 全选
- 反选
- 点复选框不进入详情
- 点卡片空白区进入详情
- 浮层固定可见
- 批量增加分类
- 批量删除分类
- 批量删除提示词确认流程

### 分类筛选收敛

需要覆盖：

- 批量增加分类后，符合当前分类筛选的新项进入结果集
- 批量删除分类后，不再符合筛选的项移出结果集

### 真实库 E2E

需要覆盖：

- 远程测试库下批量分类成功
- 远程测试库下批量删除提示词成功
- 操作后刷新或重新查询能看到持久化结果

### API 测试

需要覆盖：

- 批量删除提示词预检查
- 批量删除提示词确认删除
- 非法 confirmation token
- 空 slug 集合

## 不做的内容

本轮明确不做：

- 主分类
- 独立批量管理页面
- 跨分页全选
- 批量操作的部分成功 UI
- URL 持久化筛选状态

## 成功标准

管理员能在列表页中：

- 快速全选或反选当前结果集
- 批量增加分类
- 批量删除分类
- 批量删除提示词

并且：

- 分类始终保持平级多分类模型
- 批量操作后列表结果与当前筛选条件一致
- 不发生整页 reload
- 远程 real-db e2e 可以覆盖核心路径
